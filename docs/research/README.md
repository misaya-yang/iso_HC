# 面向2027的残差算法研究

更新：2026-09-26，R4。当前已实现一个可训练的最小候选：**伴随读写残差 `adjoint-hc`**。完整代码位于 [lm/adjoint.py](../../lm/adjoint.py)，已接入既有训练工厂。它是待验证算法，不是已获得SOTA的结论。

## 当前算法

两条残差流使用同一单位向量读出和写回：`z=c₀x+c₁m; δ=F(Norm(z)); (x,m)←(x,m)+(c₀δ,c₁δ)`。动态c只需一个连续标量线性门，没有H_res矩阵、投影求逆、离散状态管理或额外监督。

这个约束保留精确的局部residual语义，并避免读写错位的额外剪切。固定地址时，在被读取方向执行普通residual、正交方向保持；同读取/同branch/单位自作用的比较类中，伴随写回达到最佳局部条件数。动态整网稳定性不由此自动保证。

初始化使用固定符号变换的输入作为辅助carrier，路由器为零。这样初始函数严格等于共享权重的baseline，而普通NTP可产生非零路由梯度；若辅助流为零，则全对齐初始化的路由会落入死区。这个构造是可训起点，不证明已经形成有用记忆。

算法、初始化、代码和限制统一见 [architecture.md](architecture.md)，完整证明见 [theory.md §10](theory.md)。

## 实现与证据状态

- **已实现：** 两流完整Transformer、连续路由、attention/MLP/最终出口、普通NTP训练、静态地址/冻结辅助更新/零载体/复制载体对照、训练工厂配置。
- **已验证：** baseline函数匹配、梯度、局部算子、因果和样本隔离等合同；本地CPU集成训练和完整forward/backward成本。回执见 [adjoint probe](../../results/adjoint_hc_20260926/README.md)。
- **未建立：** 自然语言性能优势、GPU实际成本、规模收益、相对最强HC/AttnRes的竞争力、独立新颖性。

合成数据的短训练只证明训练链路可用，不依据其微小loss差给方法排胜负。CPU开销必须正面报告，不能用新增参数少代替成本结论。

## 贡献边界与下一决定

HC/RMT已经包含丰富读写模型；无transport、子空间投影与初始化破对称也有直接先行工作。因此贡献候选是**用严格读写对齐的几何约束，得到一个简单、有效且有成本优势的实现**，而不是宣称发明多流。

下一关键比较是同入口/同主干的自由读写、冻结辅助流和强单流增益控制，继而面对最相关的动态HC与AttnRes。若收益只是embedding长skip或路由尺度，按事实重归因。若约束损害表达力或成本不值得，不维护当前设计。

成熟训练与独立尺度的目标仍是100–150M开发、350M及约1B确认；具体依据 [roadmap.md](roadmap.md)。本轮没有下载语料或启动付费GPU。

## 保留的工程纪律

普通NTP、规则张量、有效初始化、每个组件有必要性、真实质量—成本比较。RDM及压缩优先路线不恢复；RDM原语与旧IsoHC数据作为历史资产保留。算法实现后的后续修改以观察到的问题为依据，不再用多层控制器补故事。

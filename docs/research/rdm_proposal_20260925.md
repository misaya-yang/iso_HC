# 候选架构规格：Reserved Depth Memory

更新：2026-09-25。状态：**架构假说与首版实现合同；尚未实现完整训练模块，尚无本架构的训练结果，不是已找到的 SOTA。** 当前研究决策见 [README](README.md)，证据状态见 [evidence](evidence.md)，实验顺序见 [roadmap](roadmap.md)。本文件只维护候选结构及其可证伪机制，不另建实验结果副本。

## 1. 目标与新增操作

Reserved Depth Memory（RDM，工作名）尝试把残差的工作方式从“每一步覆盖同一个累积状态，或混合所有 streams”改为：

**读取工作区 → 计算候选内容 → 申请存活期与容量 → 条件提交 → 释放到期保护。**

每个 token 保留一个即时工作向量、不可变的 embedding 锚点，以及少量持久槽位。当前分支的计算结果始终进入即时工作向量；是否进入持久槽位另行决定。持久内容的保护和释放由其预测的后续用途决定，而不是要求所有历史内容永久保存。

核心假说是：**有限容量下，预测哪些内容仍需被后续深度读取，并使写入遵守该承诺，能够同时减少无区别累积和不必要的状态干扰，从而改善质量—成本取舍。** 这是假说，不把标准残差必然“污染信息”、或所有 HC 必然不稳定当作已经成立的前提。

新增研究对象是 **future-use forecast / lifetime / admission** 与受保护写入之间的交互。attention read、槽位存储、遗忘门、稀疏写入、存活期预测和容量分配分别都有先行工作；把这些词组合起来不构成创新。只有该交互产生强控制无法解释的任务价值，才值得成为主贡献。

## 2. 第一版选择离散槽位

第一版使用彼此独立的存储槽位；“orthogonal slots”指存储索引对应互不重叠的坐标位置，**不要求槽位的特征向量彼此正交**。不对激活做 Gram–Schmidt，也不在每层施加全体槽位的 dense mixer。

暂不使用 dense-key nullspace 投影或矩阵逆来写入。那种设计会引入接近容量冲突时的小分母、键空间条件数和在线最小二乘的新颖性问题。独立槽位先检验生命周期机制是否有用；不能将暂未实现的连续子空间版本的理论收益记在本版本名下。

令每个 attention 或 MLP 分支为深度步骤 \(s=0,\ldots,N-1\)。以下量均按 token 保存；batch 和序列维省略。

| 状态 | 定义 | 写入合同 |
| --- | --- | --- |
| \(e\in\mathbb R^d\) | 本次前向的 embedding 锚点 | 深度方向不修改；不意味着 embedding 参数不训练 |
| \(w_s\in\mathbb R^d\) | 当前工作向量 | 每一步接收新候选，无论持久写入是否成功 |
| \(M_s\in\mathbb R^{K\times d}\) | 持久槽位，首批候选 \(K=4,8,16\) | 仅选中的未受保护槽位可更新 |
| \(k_{s,j}\in\mathbb R^r\) | 与槽位内容一起提交的读取键 | 受保护期间不修改；\(r\) 是单独登记的键宽度 |
| \(\mathrm{valid}_{s,j}\) | 该槽位是否已有内容 | 空槽位不参与读取 |
| \(\ell_{s,j}\) | 提交时申请并获准的保护时长 | 第一版提交后固定，不隐式续租 |
| \(\mathrm{expiry}_{s,j}\) | 第一个允许重新写入的深度步骤 | 用于计算保护状态 |
| \(\mathrm{version}_{s,j}\) | 内容版本标识 | 每次实际提交更新，用于追踪未来读取标签 |

第一版初始化 \(w_0=e\)，所有持久槽位为 invalid。空槽位存零只是实现选择，不作为额外可读记忆。\(e\) 在前向中可以使用共享引用，不能把实现中的复制成本假定为零。

## 3. 完整前向算法

### 3.1 Read：归一化读取

从当前可用的 \(e,w_s\)、槽位键和当前元数据生成查询与读取 logits。第一版查询不使用未来层状态；可使用当前 token 的状态以及已经由因果 attention 汇集的前缀信息。任何额外跨 token 控制器也必须遵守语言模型的因果 mask。

读取对象为 \([e,w_s,M_{s,1},\ldots,M_{s,K}]\)，invalid 槽位被 mask。使用非负、和为 1 的权重：

\[
\alpha_s=\operatorname{softmax}(\operatorname{score}_s),\qquad
z_s=\alpha_{s,e}e+\alpha_{s,w}w_s+
\sum_{j:\mathrm{valid}_{s,j}}\alpha_{s,j}M_{s,j}.
\]

槽位是否受保护不影响其可读性；保护仅限制写入。过期但尚未被替换的内容仍可读取。键、年龄和有效标志如何进入 logits 必须写入配置，不通过未记录的偏置暗中偏爱新内容。

这是 attention 读取，不能因为使用“记忆”名称就认为区别于 AttnRes 或 RMT。读端本身不承担新颖性主张。

### 3.2 Compute：始终保留本步计算结果

使用与对照相同的 attention／MLP 分支 \(F_s\)，形成

\[
v_s=\operatorname{cap}_C\!\left(z_s+g_sF_s(\operatorname{Norm}(z_s))\right),
\qquad w_{s+1}=v_s.
\]

其中 \(\operatorname{cap}_C(x)=x\min(1,C/\|x\|_2)\)，零向量保持为零。若使用 RMS 上限，配置必须明确对应的欧氏上限为 \(C_{\mathrm{RMS}}\sqrt d\)。输入锚点也经过相同约定的范数上限。\(g_s\) 的范围、初始化、是否按 token 条件化以及优化器分组需要预先登记；不给未经训练验证的默认值赋予理论最优意义。

“保留本步进展”只表示本次计算结果不会因为持久写入失败而被丢弃，**不表示每步都降低 loss**。范数上限是候选结构的一部分，可能损害有效表达，必须有匹配的无上限／相同上限对照。

### 3.3 Reserve：预测用途并申请持久存储

控制器根据当前信息输出候选内容的用途分数、离散保护时长，以及对可替换槽位的保留价值估计。其输入可以包含 \(e,w_s,z_s,v_s\)、当前键及元数据；不得读取部署时尚未计算的后续层状态。

步骤 \(s\) 的受保护集合定义为

\[
P_s=\{j:\mathrm{valid}_{s,j}\land s<\mathrm{expiry}_{s,j}\}.
\]

只有 \(E_s=\{1,\ldots,K\}\setminus P_s\) 可作为本步写入候选。invalid 槽位优先于需要覆盖已有内容的槽位，但不强迫每一步都提交。

准入需要同时决定：新内容是否值得持久保存、选择哪个合法槽位、保护多久、写入比例是多少。第一版每 token 每分支最多提交一次。若 \(E_s=\varnothing\)，**拒绝本次持久写入，保留 \(w_{s+1}=v_s\)**。不得为使训练运行而偷偷覆盖“最不重要的受保护槽位”。这种行为若将来需要研究，必须作为另一种明确违反原保护合同的架构。

第一版不自动续租、不提前撤销已承诺的保护，也不临时增加容量。它们可以成为后续显式变体，不能在首版实现中隐式出现。

### 3.4 Commit：只修改一个合法槽位

若准入选择 \(j\in E_s\)，则

\[
M_{s+1,j}=(1-\eta_s)M_{s,j}+\eta_s v_s,
\qquad 0\le\eta_s\le1.
\]

invalid 槽位视为零内容。首个合同实现可以使用 \(\eta_s=1\)，以便键和值的语义最清楚；可学习凸替换另作显式配置。其余槽位保持不变。

所选槽位的 key、valid、lease、expiry 和 version 与内容**一起提交**。使用凸替换时，新的 key 和用途预测必须对应提交后的混合内容，不能把它标记成完整保存了 \(v_s\)。\(\eta_s=0\) 应视为未提交，不凭空刷新保护时长或内容版本。

设本次获准保护时长为 \(\ell_s\in\{0,\ldots,L_{\max}\}\)，则

\[
\mathrm{expiry}_{s+1,j}=s+1+\ell_s.
\]

这表示内容从步骤 \(s+1\) 开始可读；\(\ell_s=0\) 不获得下一步写保护，\(\ell_s=1\) 在步骤 \(s+1\) 的写入阶段受保护，于步骤 \(s+2\) 可替换。实现必须为这些边界留下可读回执。

### 3.5 Release：到期只解除保护

步骤末尾为下一步骤更新保护标志：\(P_{s+1}=\{j:\mathrm{valid}_{s+1,j}\land s+1<\mathrm{expiry}_{s+1,j}\}\)。到期仅解除锁，**不删除值、不清空 key、不令 valid 变为 false**。历史内容直到被合法替换之前仍可被读取。

最终输出另执行一次登记在案的归一化读取 \(z_N=\operatorname{Read}(e,w_N,M_N)\)，然后进入标准 final norm 与词表投影。该最终读取也计入未来用途标签；不能让训练标签忽略最终真正消费记忆的位置。

### 3.6 伪代码

```text
e = cap(embedding); w = e
slots = empty(K); metadata = invalid(K)
for s in attention_and_mlp_steps:
    protected = valid & (s < expiry)
    z = normalized_read(e, w, slots, keys, valid)
    v = cap(z + bounded_gain[s] * branch[s](norm(z)))
    proposal = forecast_and_request(current_states, v, metadata)
    eligible = ~protected
    decision = admission(proposal, eligible)
    w = v
    if decision.accept:
        assert eligible[decision.slot]
        replace_one_slot_convexly_and_commit_metadata(decision, v)
    release_only_expired_locks_for_next_step()
output = head(final_norm(normalized_read(e, w, slots, keys, valid)))
```

## 4. 可以承诺的稳定性与不能承诺的事情

如果 \(e,w_s,M_{s,j}\) 的范数不超过 \(C\)，归一化非负读取保证 \(\|z_s\|\le C\)；cap 保证 \(\|w_{s+1}\|\le C\)；凸替换保持槽位范数不超过 \(C\)。从合法初始化出发可逐步归纳。这是**激活范数与局部写入合同**，不是性能定理。

受保护槽位的内容和键在其保护期内不被持久写入改变。这不保证后续 attention 会正确找到它，也不保证读出混合 \(z_s\) 不变：query、其他值和 softmax 分母都可能变化。必须区分“内容仍在”“可以被查询识别”“对最终任务有用”三个命题。

本设计避免反复应用一个无约束 \(K\times K\) transport，但 branch Jacobian、查询和 key 的导数、softmax 温度、门控、norm 以及 hard selection 仍可带来优化问题。**不得从 bounded state 推出全网 Jacobian 等距、梯度稳定、无训练崩溃或多流问题已解决。**

锁满时拒绝写入是明确的容量行为，不是程序错误。若锁满频率很高，模型实际上依赖即时工作向量，持久记忆可能没有价值；应报告而不是通过隐式覆盖使图表好看。

## 5. Forecast 的训练难点是研究内容

### 5.1 不能使用自我确认的标签

只给“目前没有被淘汰的槽位”统计未来 attention 权重，会产生严重选择偏差：被提前淘汰的内容再也不能被读取，于是被错误标成不重要；控制器从自身淘汰决策得到自我确认。

训练标签必须按**内容版本**追踪，而不是按槽位索引追踪。重用同一索引后的读取不能算成旧内容的未来用途。未来读取标签应 detach，控制器不能通过修改这些标签本身来降低辅助损失。

至少需要两层反事实检查：

1. **Shadow 候选记录。** 训练诊断保留被拒绝或被替换的 key／内容版本，使用后续实际 query 评估其潜在匹配，并采样不同合法准入策略获得覆盖。影子评分只是当前轨迹下的潜在匹配，不等于“如果保留该内容，未来网络真正会怎样”。
2. **抽样 replay。** 对部分容量冲突点，从共同状态重算后续 routing，比较保留、释放或拒绝的任务后果。必须重新计算控制器；固定后续 routing 的 replay 只能提供条件干预。以此校准 shadow 评分，并检查未来 attention 质量是否真的对应任务价值。

使用全历史 teacher 或额外重放会增加训练成本，必须计入；如果它给候选提供了额外监督，关键对照也要获得匹配监督，或单独报告这一成本和贡献。teacher／shadow 可以产生训练标签，不能成为推理时暗藏的无限容量记忆。

### 5.2 Hard policy 不会自动可训练

槽位选择、是否提交和整数存活期含离散决策。第一版合同实现使用固定策略，先验证前向语义；这**不等于**已经得到 learned forecast。

可考察以 detached shadow／replay 标签单独训练 forecast，再冻结进行首轮 LM 比较；之后评估交替更新。主干变化会导致标签分布变化，这个问题不能省略。通过选中槽位的内容仍可正常反传，但索引选择本身没有普通路径导数。

straight-through、策略梯度或 soft relaxation 都只能作为明确登记的训练方案。前者有偏差，后者有方差与额外成本；soft 训练若允许改写受保护内容，就不满足部署时的硬保护合同。需要测训练—推理差距，不能在叙事中自动假定两者等价。

## 6. 与直接竞争方法的区别仍待证明

文献身份与核查范围由 [literature](literature.md) 统一维护。本表是设计合同，不宣称首次发明以下单项操作。

| 竞争／已知机制 | 已经覆盖什么 | RDM 必须额外证明什么 |
| --- | --- | --- |
| DNC 的 allocation／free（2016）及一般外部记忆 | 基于使用情况分配、释放、读取与写入 | 预测后续深度用途与硬保护承诺优于通用 usage/free；不能把存活期视为新发明 |
| AttnRes | attention 读取深度历史 | 固定容量下的生命周期管理有任务与成本价值；相同容量的 attention cache 是必要对照 |
| RMT | 独立扩展残差状态／memory capacity | 状态数以外的机制收益，控制分支宽度、参数、tokens 与实际成本 |
| DDL | selective rewriting | 保护承诺与准入策略提供超出普通选择性改写的收益 |
| xHC | 稀疏槽位更新、写入瓶颈和时间使用 | 在相同稀疏写入数与容量下，预测用途的保护／释放仍有增量 |
| mHC／oHC | 对 mixing 的稳定性与几何约束 | 直接的任务与质量—成本优势；不能只比较本方法不执行的 transport 谱 |
| DeltaNet／在线 LS／TTT 类更新 | 关联记忆与误差驱动写入 | 本版本不是借用这些更新后改称深度创新；若扩展为连续子空间写入，必须重新核查这条直接竞争线 |

最有可能的新内容是以下交互，而非模块清单：没有用途／释放管理，保护很快耗尽容量；没有保护合同，准入后仍可破坏其他需要保留的内容。两者结合若能维持可用容量并兑现后续读取价值，才可能形成新的残差工作流。

## 7. 必须面对的对照与失败方式

同一读端、分支与容量下，至少比较普通循环写入、FIFO、基于近期读取的替换、通用 usage/free 分配以及 learned future-use。不能仅赢一个弱随机淘汰策略。

保护与 forecast 的核心比较应包含：无保护的 learned replacement、固定期限保护、基于近期使用的保护、预测未来用途的保护。若声称二者交互，还需要保持其他机制一致的匹配组合，区分改进来自额外参数、额外 teacher 信息、拒绝写入率还是保护本身。

锁满、过长 lease、过早释放、forecast 失准和陈旧记忆均为预期失败模式。必须包含需要覆盖旧结论的任务或样本，避免用只需无限保留的玩具任务奖励永不释放。单次删除导致掉点不证明 lease 预测正确；应比较后续重算与从头训练。

真实 LM 的主要竞争仍是充分调好的单流 residual gain、动态 HC，以及相关 AttnRes／RMT／DDL／xHC。保持相同分支宽度回答机制问题，匹配总计算和实际成本回答实用问题；两种比较分别报告。

## 8. 成本与可实现性

每 token 的槽位读取为 \(O(Kd)\)，一次提交为 \(O(d)\)，key 打分为 \(O(Kr)\)；query／key 投影及控制器成本另计，例如固定键宽 \(r\) 的投影可能为 \(O(dr)\)。不执行每层 \(K^2\) 的全槽位 mixing。以上只描述局部算子，不证明端到端速度更快。

前向活动状态约为 \((K+2)d+Kr\) 个数及 \(O(K)\) 元数据。训练若保存每步工作区快照，激活内存可以达到 \(O(NKd)\)，不能宣传整个训练仅需 \(O(Kd)\)。checkpoint、稀疏更新记录或定制 backward 可以改变实际开销，必须先实现、测量，再宣称节省。

hard selection 的 gather/scatter、不同 token 的分支、槽位复制、编译行为以及对 kernel 融合的影响均可能抵消算术节省。shadow、teacher、replay 与 forecast 训练缓存的成本也要记录。报告稳态吞吐、峰值显存、编译、评估和训练总成本，不只给理论 FLOPs。

## 9. 第一版交付与推进条件

首版只需把以下合同变成可运行、可检查的模块：空槽位 mask；受保护内容与 key 不变；全部受保护时拒绝持久写入但更新 workspace；lease 的深度边界；到期不删除；内容与元数据同提交；version 标签不串代；因果读取；范数归纳。它是**实现正确性**，不是机制成功。

随后先测强固定策略与成本，确认工作区本身可用，再训练 forecast 并验证反事实标签。若 learned lease 不能超过 FIFO、近期使用和通用 allocation/free，就不能把未来用途预测写成贡献。若赢了这些策略却输给强架构在质量—成本上的取舍，应把问题定位为架构仍无实用优势，而非转用记忆命中率替代主终点。

当前 RDM 是最值得优先实现并接受反证的架构候选。成为可投稿的核心结果需要：新颖性进一步核实、保护与生命周期的独立和交互证据、成熟 LM 训练、强架构竞争、独立规模／深度确认，以及真实成本优势。**这些条件尚未完成，不将本规格写成 SOTA、稳定性问题的终解或 solid-accept 保证。**
